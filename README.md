# Проценка автозапчастей

Клиент для подбора автозапчастей по артикулу. Сначала показываются производители этой детали, затем предложения и аналоги выбранного бренда. Данные приходят из сервиса Favorit `hsprice`.

## Как пользоваться

В поле «Артикул» вводится номер детали. Поиск начинается сам, через короткую паузу после ввода, если в номере хотя бы три символа. Кнопка «Поиск» повторяет запрос с тем, что сейчас введено, и не отвечает, пока запрос ещё идёт.

Дальше два шага.

1. **Производители.** Карточка показывает бренд и `Арт.: номер`, под ними — наименование. На экране пять карточек, остальные листаются внутри списка. Рядом с заголовком — сколько производителей нашлось.
2. **Предложения.** Блок появляется, когда список производителей уже получен. После выбора бренда строится таблица: название, производитель, номер, цена и остаток. Строка — это конкретный склад. Сначала идёт выбранная позиция, затем аналоги; внутри группы раньше стоят позиции с остатком. Рядом с заголовком — сколько строк нашлось и сколько их показывать сразу: 5, 10, 15 или 20. Остальное доступно прокруткой.

Цену и остаток приложение берёт со склада. Если складов нет, строка всё равно есть: цена и остаток нулевые.

Заголовки таблицы сортируются. Первый клик — по возрастанию, второй — по убыванию, третий возвращает исходный порядок. Ширину столбца можно потянуть за границу: растёт текущий столбец, соседний сужается до ширины своего заголовка, затем следующий.

Успешный ответ хранится в памяти вкладки одну минуту. Повтор того же артикула или бренда в эту минуту не ходит в сеть. Когда минута прошла, следующий запрос обновляет сохранённый ответ. Кнопка «Поиск» всегда запрашивает список заново. Ошибки сети, таймаут сервиса и текст ошибки из ответа не запоминаются и показываются с кнопкой повтора. Знакомые формулировки сервиса, включая превышение лимита запросов, выводятся по-русски. Незнакомый текст остаётся как в ответе.

## Запуск

```bash
cp .env.example .env
npm install
npm run dev
```

В `.env.example` уже стоит демо-ключ из документации API.

```bash
npm test
npm run build
```

Переменные:

- `VITE_FAVORIT_API_URL` — адрес `hsprice`
- `VITE_FAVORIT_API_KEY` — ключ покупателя

## Как устроено

Одно Vite-приложение. React и Redux Toolkit, без TypeScript. Стили — Bootstrap 5.

Запросы выполняет класс `HsPriceApi`: один GET с параметрами `key`, `number` и, на втором шаге, `brand`, `analogues=on`, `info=on`. Контракт описан в `docs/openapi.yaml`. Клиент читает тело как JSON и не смотрит на `Content-Type`: сервис может вернуть ошибку в JSON и при HTTP 200 с заголовком `text/plain`. Свой таймаут клиент не ставит.

Страница поиска — единственное место, которое читает store. Форма, список и таблица получают данные пропсами. Кэш, нормализация ответа и сортировка живут отдельно от компонентов.
